# 06. 出題タイプ仕様(qtypes)

Quiz シーンは問題オブジェクトの `type` で該当プラグインにディスパッチする。全タイプ共通の契約:

```ts
interface QType {
  readonly name: QTypeName;
  mount(scene: Phaser.Scene, q: Question, api: QTypeApi): void;  // 問題を描画し入力を待つ
  destroy(): void;
}
interface QTypeApi {
  correct(): void;                  // 正解確定(共通演出+次問へは Quiz シーンが担う)
  wrong(correctDisplay: string): void;   // 不正解確定(正解の提示文字列を渡す)
  sfx(name: string): void;
}
```

- 判定は「確定操作」で行う(選んだ瞬間に確定するのは choice 系のみ。並べ替え系は「できた!」ボタンで確定し、途中でやり直せる)
- 共通演出(正解パーティクル・コンボ・不正解シェイク・正解提示)は Quiz シーン側の共通処理。プラグインは自分の盤面の演出(カードが弾む等)だけ担当
- 部分正解は作らない(1問=正解/不正解の2値。低学年の認知負荷を上げない)
- 全タイプで「もんだいを よみあげない」前提(音声なし)のため、**問題文は1行・対象は大きく表示**が原則

## v1 実装タイプ(7種)

### 1. `choice` — 4択(基本形)
- 画面: 問題文+(任意で)大きな対象表示(漢字1字など)+選択肢ボタン2×2(3択時は縦3)
- 操作: 選択肢タップで即確定
- データ: `choices[]`, `ans`, `img?`(絵選択肢: 選択肢がテキストでなく絵のバリエーションを含む)
- 用途: 漢字よみ・カタカナ・語彙・読解・推敲 ほか大半。旧 `witch`(どれかな?)は絵選択肢の choice として統合
- 演出: 正解ボタンがバウンス。不正解時は正解ボタンがグロー

### 2. `match` — 線むすび
- 画面: 左列3〜4枚(例: 漢字)、右列に対応札(例: よみ)をシャッフル配置
- 操作: 左→右の順にタップでペア確定(ドラッグ不要のタップ2回方式。誤ペアはその場でシェイクし選び直し)。全ペア成立で1問正解
- データ: `pairs: [left, right][]`(3〜4組)
- 判定: 誤ペア試行が2回以下なら正解扱い、3回以上は不正解(甘め設計)
- 演出: 成立ペアは線が引かれて両札が同色に点灯

### 3. `arrange` — 並べ替え(語順・文順・出来事順)
- 画面: 上部に空スロット、下部にシャッフルされたカード(語 or 文、3〜4枚)
- 操作: カードをタップ→次の空スロットへ飛んでいく。配置済みカードをタップすると手元に戻る。「できた!」で確定
- データ: `cards[]`(正解順で保持。表示時にシャッフル。**シャッフル結果が正解順と一致したら再シャッフル**)
- 用途: 文の組み立て(かきかた)、出来事の順序(よみとき)。学年が上がると段落構成・意見文構成に発展する**本作の看板タイプ**
- 演出: 確定時、正しい並びなら左から順にカードが点灯していく

### 4. `fillblank` — 穴埋め選択
- 画面: 穴あき文(穴は光る□)+穴ごとの選択肢チップ(2〜3択)
- 操作: 穴をタップ→候補が出る→選ぶ。全穴埋めで自動確定
- データ: `text`(`{0}` 形式の穴)、`blanks[][]`(穴ごとの候補)、`ans[]`
- 用途: てにをは(は/わ・へ/え・を/お)、将来: つなぎ言葉・敬語

### 5. `insert` — 挿入(句読点・かぎ)
- 画面: 文を1文字ずつ表示し、文字間の「すき間」がタップ可能なマーカーに
- 操作: パレットから記号(。、「 」)を選ぶ→打つ位置のすき間をタップ。「できた!」で確定
- データ: `chars`, `marks: {pos, mark}[]`(正解位置)
- 判定: 全記号が正しい位置で正解。位置ズレ1箇所までのやり直し1回を許容
- 用途: 1年: 。とかぎ → 3-4年: 読点の位置

### 6. `dig` — ほりだし(あそび回・前作独自形式の国語版)
- 画面: 3×3 の砂山。各砂山に札(漢字など)が埋まっている
- 操作: お題(例: 「『やま』と よむ じは どこ?」)に合う砂山をタップ→掘る演出→当たりで宝がチラ見え
- データ: `board[9]`, `targetIndex`, `prompt`
- 演出: 掘るたび砂ぼこりパーティクル。ハズレは「スミゾーの すみ」が出てくる(コミカルに)

### 7. `shiritori` — しりとり(あそび回・言葉遊び)
- 画面: 中央にしりとりの鎖(これまでの語)。下に候補3枚(絵+ことば)
- 操作: 鎖の最後の音につながる語をタップ。8問連続で鎖が完成し洞窟を抜ける
- データ: `chain` 開始語+各手番の `candidates[3]`(正解1+ダミー2。「ん」で終わる引っ掛け候補を混ぜる)
- 演出: つながるたび鎖が伸びて画面が奥へスクロール

## 出題ロジック(gen)の共通ルール

1. 同一クイズ内で `key` の重複禁止(重複したら再生成。上限リトライ後はプールから未出題を直接選ぶ)
2. 選択肢に正解と同表記・紛らわしすぎる同音語を混ぜない(`choices` 内の文字列重複禁止)
3. 誤答選択肢は同プール内から選ぶ(意味のあるダミー。デタラメ文字列を生成しない)
4. かくにんテスト・ボスの mix は、その島で既出のタイプのみ使う(初見タイプをテストに出さない)
5. gen は純関数+注入 rng(`docs/05` §4)。1000回実行しても不変条件(ans 範囲内・choices 重複なし・key 形式)を守ることをユニットテストで保証(`docs/08`)
