# 08. 検証・テスト

前作は jsdom による盲目検証だったが、本作は **実ブラウザ(Chromium)で動かして目で見る** ことを標準にする。CI で全て自動実行。

## 1. ユニットテスト(Vitest)— 層1・層2

### gen 関数(全タイプ必須)
各 gen について seed 付き rng で **1000回以上** 実行し、不変条件を検証:
- `ans` が範囲内 / `choices` に文字列重複なし / 正解が choices に必ず含まれる
- `key` が一意形式 / 同一クイズ構築で `key` 重複が発生しない(mix 含む)
- arrange: シャッフル結果が正解順と一致しない / match: pairs の左右に重複なし
- 誤答が正解と同表記にならない(「やすい/たかい」問題: 反対語プールに多義があるため要注意)

### データ検証(zod スキーマ)
- `data/**/*.json` 全ファイルをスキーマ検証するテスト(CI で壊れたデータを止める)
- 追加ルール: ステージ `id` 全体一意 / `gen` 参照名がレジストリに存在 / プール参照が存在 / 漢字プールが学年別漢字配当表と一致(g1=80字) / セリフの禁止語チェック(「まちがい」「だめ」等の否定語リスト・下品語リスト)

### セーブデータ
- v1 スキーマの読み書き / 壊れた JSON・未知バージョンからの復旧(初期化+バックアップ退避) / エクスポート→インポートのラウンドトリップ

## 2. E2E(Playwright + 同梱 Chromium)

### 通しシナリオ(スモーク)
1. 初回起動 → コンパス命名 → うみえらび表示
2. 1ねんのうみ → 挑戦状(初回のみ表示・既読で再表示なし)→ しまえらび
3. もじのしま → ステージ1 → 全問正解でクリア → ★3+宝物+負け惜しみ → 「つぎへ」導線
4. 同ステージで正答率60%未満 → 不合格 → **敵が出ないこと**・励まし表示 → 再挑戦
5. ステージ2 が解放されている / ステージ3 はロック
6. ずかんに宝物+船長コメント / おうちのひとに成績+skillRef
7. リロードして進捗が残る(localStorage)
8. 全 qtype を最低1回操作するシナリオ(match のタップ2回方式、arrange の戻し操作、insert のすき間タップ)

### スクリーンショット運用(必須)
- 主要画面(うみえらび/しまえらび/しまマップ/各qtype/けっか/ずかん)を **810×1080 で撮影**し、CI アーティファクトに保存
- **PR には代表スクショを添付**する(レビューは見た目で行う)。視覚リグレッションの基準画像比較は任意(閾値ゆるめの toMatchSnapshot から始める)

## 3. 品質ゲート(その他)

| 項目 | 方法 |
|---|---|
| コントラスト | 文字色×背景が WCAG AA(4.5:1)以上。テーマ配色定義に対する計算テストを CI に含める |
| パフォーマンス | Lighthouse(CI・モバイル設定)で Performance 85+ / PWA 要件充足。バンドルサイズ監視(10MB 予算) |
| オフライン | Playwright で SW 登録後にオフライン化→リロード→起動できること |
| フォント | サブセットに教育漢字1026字+かな+記号が含まれるかのビルド時チェック(豆腐検出) |
| アニメひかえめ | reducedMotion 設定でトゥイーン・パーティクルが抑制されること |
| ダジャレ校正 | `script.json` 等のセリフ全件を一覧化する npm script(`npm run lint:dajare`)を用意し、4基準チェック欄付き Markdown を生成 → 人間(開発者)が承認してからマージ |
